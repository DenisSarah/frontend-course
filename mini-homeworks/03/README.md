# Мини-ДЗ 3

Подбор профессиональных игроков Dota 2 в состав на матч. В каталоге 30 реальных игроков, по шесть на позицию. Статистика рассчитана по снимку 600 матчей OpenDota от 24.10.2026. Состав хранится в памяти до обновления страницы.

```text
src/
  App.jsx               — memo, useCallback и useMemo
  Before.jsx            — вариант без ручных оптимизаций
  components/
    DraftPage.jsx       — состав, фильтры и название в родителе или ребёнке
    PlayerCard.jsx      — обычная и memo-карточки
  data.js               — позиции, игроки и сведения о снимке
  players.json          — реальные профили и по 20 доступных матчей
  stats.js              — расчёт статистики
  draft.js              — поиск, сортировка и выбор игроков
  useRenderLog.js       — счётчики обновлений в dev-консоли
  main.jsx              — выбор варианта и запуск React
  styles.css            — стили
vite.config.js          — React Compiler для режима compiler
scripts/update-players.mjs — обновление снимка через OpenDota API
```

Из корня репозитория:

```bash
pnpm install
pnpm dev:03
```

Открыть http://127.0.0.1:5177. Это вариант с memo и состоянием названия внутри дочернего компонента. На каждой позиции можно выбрать одного игрока; новый игрок заменяет предыдущего.

## Данные игроков

Игроки, их позиции и аккаунты сверены с [Dota2ProTracker](https://dota2protracker.com/players). Используются подтверждённые аккаунты; у Ame и Nisha — дополнительные аккаунты, с которых они также играли турнирные матчи. Позиция в карточке — роль профессионального игрока; выборка может содержать игры на других ролях.

Матчи получены из [OpenDota API](https://docs.opendota.com/), метод `GET /players/{account_id}/recentMatches`. Это до 20 последних доступных матчей конкретного профиля, а не вся карьера. Период показан на каждой карточке в UTC. В JSON сохранены идентификаторы матчей и адреса источников.

- Победы — доля выигранных матчей в выборке, округлённая до целого процента.
- KDA — сумма убийств и помощи, делённая на сумму смертей; если смертей нет, делитель равен 1.
- GPM — среднее золото в минуту по доступным значениям матчей, округлённое до целого.

Точный MMR не подтверждён источником и не отображается. Недоступные значения показываются как «—».

Сайт работает с локальным снимком и не делает запросы при каждом открытии. Обновить данные из корня репозитория:

```bash
pnpm --filter @frontend-course/mini-03 update:players
```

Нужен интернет. Скрипт заменяет снимок только после успешной загрузки и проверки всех 30 игроков; при ошибке прежний файл остаётся на месте.

Для сравнения, также из корня:

```bash
pnpm --filter @frontend-course/mini-03 dev:baseline
pnpm --filter @frontend-course/mini-03 dev:manual
pnpm --filter @frontend-course/mini-03 dev:compiler
```

| Вариант | Порт | Изменить название: App | Изменить название: карточек |
|---|---|---:|---:|
| Без оптимизаций | 5178 | 1 | 30 |
| memo + useCallback + useMemo, название в родителе | 5179 | 1 | 0 |
| То же, название в ребёнке | 5177 | 0 | 0 |
| Before + React Compiler | 5180 | 1 | 0 |

При изменении названия в варианте с состоянием в ребёнке обновляется только `LocalRosterName`, родитель и карточки не обновляются.

Проверка: открыть Console, дождаться загрузки и изменить название. `App` — родитель, `RosterName` — локальное поле названия, `PlayerCard player-ACCOUNT_ID` — одна из 30 карточек. Счётчики через effect показывают завершённые обновления компонентов, а не количество изменений DOM. Начальная загрузка в таблице не учитывается.

`memo` пропускает карточки с прежними props. `useCallback` сохраняет обработчик выбора. `useMemo` кеширует поиск, сортировку и статистику матчей. `setName` в `LocalRosterName` обновляет ребёнка без обновления родителя.

[React Compiler](https://react.dev/learn/react-compiler/installation) включён только для режима compiler и обрабатывает `Before.jsx` без ручных оптимизаций. При изменении названия список карточек берётся из кеша.

```bash
pnpm --filter @frontend-course/mini-03 build
pnpm --filter @frontend-course/mini-03 lint
pnpm --filter @frontend-course/mini-03 preview
```

Сборка создаёт четыре варианта в `dist/`. Preview открывает основной вариант на порту 5177; перед ним нужно остановить dev-сервер на этом порту.
