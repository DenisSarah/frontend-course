# Журнал матчей Dota 2

После игры можно записать героя, победу или поражение, убийства, смерти, помощи и короткую заметку. В журнале можно открыть запись по ссылке, исправить её, удалить или оставить в списке только победы или поражения.

## Запуск

Нужны Node.js 24.19+ и pnpm 11.25.0. Из корня репозитория:

```bash
pnpm install
pnpm dev:hw02
```

[Журнал](http://127.0.0.1:5182/matches) и [API](http://127.0.0.1:5182/api/matches) работают на одном порту. Express обслуживает запросы к API, Vite — клиент. При запуске сервера в памяти появляются шесть учебных матчей. Обновление вкладки сохраняет изменения, перезапуск сервера возвращает начальные записи.

Для запуска собранной версии остановите dev-сервер и выполните:

```bash
pnpm --filter @frontend-course/homework-02 build
pnpm --filter @frontend-course/homework-02 start
```

## Страницы

| Адрес | Что открывается |
| --- | --- |
| `/matches` | Все матчи |
| `/matches?result=win`, `/matches?result=loss` | Победы или поражения |
| `/matches/6` | Пример записи |
| `/matches/new` | Новый матч |
| `/matches/:id/edit` | Редактирование матча |

## API

| Метод | Адрес | Результат |
| --- | --- | --- |
| GET | `/api/matches` | Массив матчей. Фильтр `?result=win` или `?result=loss` применяется на сервере |
| GET | `/api/matches/:id` | Одна запись |
| POST | `/api/matches` | Созданная запись с новым ID, статус 201 |
| PUT | `/api/matches/:id` | Обновлённая запись |
| DELETE | `/api/matches/:id` | Статус 204, без тела ответа |

Для POST и PUT нужен заголовок `Content-Type: application/json`. Пример тела:

```json
{"hero":"axe","result":"win","kills":7,"deaths":3,"assists":14,"note":"Удалось выиграть драку у Рошана."}
```

Сервер проверяет героя, результат и целочисленные показатели от 0 до 999. Заметку можно пропустить, её длина ограничена 500 символами. Некорректные данные дают 400, отсутствующая запись — 404. Текст ошибки приходит в поле `error`.

## Структура

В `src/pages` лежат список, карточка и форма. Функции в `src/api.ts` выполняют HTTP-запросы. Компонент `Resource` показывает загрузку и ошибку с кнопкой повтора. Когда меняется URL запроса, он отменяет старый запрос через `AbortController`, поэтому запоздавший ответ не меняет текущий список.

В `server/routes.js` находятся маршруты и проверка полей, в `server/seed.ts` — начальные матчи. Справочники героев и результатов в `shared/options.ts` используют и клиент, и сервер.

## Как проверить

[Короткая демонстрация журнала (MP4)](docs/demo.mp4)

Выберите «Поражения» и обновите вкладку. Фильтр останется в адресе, а в Network инструментов разработчика будет виден запрос `GET /api/matches?result=loss`. Создайте матч, поменяйте результат на странице редактирования, затем удалите его. В Network появятся POST, PUT и DELETE, а журнал покажет результат каждого действия.

Изображения героев и оформление основаны на материалах Valve.
